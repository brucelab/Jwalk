# Running Jwalk from a checkout

How to run this version of Jwalk from a checkout, with the launcher and its own virtual environment, and how to give chains in a crosslink list. The chain advice here is also in `README.txt`.

## One-time setup

The launcher expects a virtual environment at `Jwalk/src/venv` with NumPy and Biopython. From the `Jwalk/` directory of the checkout:

```
python3 -m venv src/venv
src/venv/bin/pip install -r requirements.txt
```

Use Python 3.8 or newer (`setup.py` requires 3.8+). If your default `python3` is older, name a newer interpreter explicitly, e.g. `python3.12 -m venv src/venv`. Jwalk has been tested with Python 3.12, NumPy 2.5.4 and Biopython 1.88; other versions have not been tested.

The venv is not stored in git (`.gitignore` excludes it), so it has to be created in each new checkout. If it is missing, the launcher says so and prints these commands.

## Running

Run the launcher from the directory that holds your `.pdb` or `.cif` files. Results are written to `./Jwalk_results/` in that directory.

```
/path/to/Jwalk/src/jwalk-launcher -i model.pdb
```

To get a short command, link the launcher onto your `PATH`. Pick a name that doesn't shadow another `jwalk` already on your `PATH` (check with `command -v jwalk`):

```
ln -s /path/to/Jwalk/src/jwalk-launcher ~/bin/jwalk-opt
jwalk-opt -i model.pdb
```

The launcher follows symlinks, so it finds its venv and code from wherever it is linked.

### Examples

```
jwalk-opt -i model.pdb                       # SASDs between all lysine pairs
jwalk-opt -i model.pdb -xl_list pairs.txt    # specific crosslinks from a list
jwalk-opt -i model.pdb -aa1 ASP -aa2 LYS     # other residue types (both needed)
jwalk-opt -i model.pdb -max_dist 30 -ncpus 8
jwalk-opt -i model.pdb -ligand                # ligands and ions block the path too
jwalk-opt -i model.pdb -ligand -surface       # ... and freesasa sees them as well
jwalk-opt -i model.cif                       # mmCIF works the same way
jwalk-opt                                    # every .pdb, .cif and .mmcif file in the current directory
```

### Options

| Option | Meaning |
|---|---|
| `-i FILE` | input PDB or mmCIF file. The path may include directories; results still go to `./Jwalk_results/` and are named from the file name, so two inputs with the same file name in different directories overwrite each other's results. |
| `-xl_list FILE` | calculate only the crosslinks in a list (format below) |
| `-lys` | lysine to lysine crosslinks (the default) |
| `-aa1 AAA`, `-aa2 AAA` | start and end residue type as three-letter codes, e.g. `ASP`. Give both. |
| `-max_dist N` | maximum crosslink distance in Angstroms, a whole number (default 60) |
| `-vox N` | voxel size in Angstroms, a whole number of at least 1 (default 1) |
| `-ncpus N` | number of CPUs (default: all) |
| `-ligand` | treat non-water `HETATM` records (ligands, ions, cofactors) as obstacles in the solvent accessible surface. Off by default, so hetero atoms are ignored as in the original Jwalk. Modified residues (MSE, ...) need the flag with PDB input but are always included from mmCIF input. Water is never included. See `20261027-ligand-mode.md`. |
| `-surface` | use freesasa to decide which residues are solvent accessible. Needs the `freesasa` command on your `PATH` (FreeSASA 2.0 or 2.1). With `-ligand`, freesasa is also given the ligands (but not water). |

A value that isn't a whole number for `-vox`, `-max_dist` or `-ncpus` is reported as a usage error.

## Crosslink list format and chains

A crosslink list is a text file with one crosslink per line:

```
residue1|chain1|residue2|chain2|
```

For example `34|A|56|B|` is residue 34 of chain A to residue 56 of chain B. Blank lines are ignored. A line that doesn't have the four fields stops the run and reports its line number.

### Structures with no chain

**Leave the chain field empty (PDB files).** A lowercase `x` does not work: Jwalk reads an empty chain field as a blank chain, which is how a PDB file without chain letters is read, and `x` is looked up as a chain named `x`. This was tested on a copy of `Examples/test.pdb` with the chain letters removed:

| Crosslink line | Result |
|---|---|
| `56\|\|98\|\|` | works |
| `56\| \|98\| \|` (a space in each chain field) | works |
| `56\|x\|98\|x\|` | every residue reported "not in pdb structure", 0 SASDs |

So for a structure with no chain, write:

```
34||56||
```

Chain letters are matched exactly against column 22 of the PDB `ATOM` lines, including case. For mmCIF input the chain is the author chain, `auth_asym_id`, which is never blank, so always give it.

## Notes

* The code reads an empty chain field as a blank chain (`GridTools.process_input_crosslinks`).
* `x` is not treated as "no chain" because it is also a valid chain letter in real PDB files, so a crosslink to a real chain `x` would be misread. Leaving the field empty avoids that ambiguity.
